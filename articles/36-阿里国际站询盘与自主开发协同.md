## 平台与自主开发不是二选一

做外贸的获客渠道大致两类：**平台**（阿里国际站、中国制造网、环球资源）花钱买流量，**自主开发**（展会、领英、谷歌、海关数据、老客户转介绍）花时间换客户。

常见两种极端：

- **只做平台**：询盘量看着不少，但同质化竞争激烈，价格被压到底，一停投放询盘归零，公司没有自己的客户资产
- **只做自主开发**：获客慢、周期长，新业务员三个月开不出单，团队撑不住

真正有效的做法是**两条线分工**：平台负责"量"和"快速验证产品与价格带"，自主开发负责"质"和"沉淀可复用客户资产"。判断标准不是哪个渠道更好，而是**每个渠道的获客成本与转化率是否说得清**。

## 平台询盘的真实成本结构

平台询盘最容易被误算的地方：只算"年费 ÷ 询盘数"，得出一个看起来很便宜的单条询盘成本。

实际成本项：

| 成本项 | 说明 |
|---|---|
| 平台年费/会员费 | 基础门槛，与询盘量不完全挂钩 |
| P4P 点击费 | 关键词竞价，是真正的变量成本 |
| 旺铺装修与详情页制作 | 一次性 + 持续优化 |
| 运营人力 | 专职运营 0.5-1 人，或业务员兼做 |
| 询盘处理人力 | 每条有效询盘平均 20-40 分钟初筛与回复 |
| 样品与打样 | 平台客户索样比例通常高于自主开发客户 |

按这个口径，一条"有效询盘"（能对话、有明确需求）的成本往往是表面数字的 2-3 倍。而**成交转化率**才是关键：100 条询盘成 2 单和成 8 单，单客获取成本差 4 倍。

所以要算的不是"询盘多少钱一条"，而是**单个成交客户的获取成本**，并且按产品线、按国家分开算——整体平均值会掩盖掉"某类产品在平台上根本不赚钱"的事实。

## 响应时效：平台询盘的第一道生死线

平台询盘有个残酷特性：**同一个询盘同时发给 5-10 家供应商**。客户通常只认真回复前 3 家，后面的进"备选"。

这意味着响应速度的权重高于话术质量。行业里常用的经验值：

- **5 分钟内**首次响应：进入客户视野的概率最高
- **1 小时内**：仍有机会，但已处于比价队列
- **24 小时后**：多数情况等于没发

要做到 5 分钟响应，靠人不现实（时差、会议、下班）。必须靠机制：

1. **询盘统一入口**：所有平台询盘进同一个池子（而不是分散在各业务员账号后台），避免"人不在就没人看到"
2. **值班表 + 移动端提醒**：按小时排班，询盘进池推送到手机，5 分钟内认领
3. **首响模板分层**：不是群发模板，而是按询盘类型（要报价/要样品/问参数/纯打听）准备 3-4 套首响框架，业务员填关键信息即可发送
4. **首响时效纳入考核**：只看"是否 5 分钟内首响"这一个指标，比看回复率更能反映执行力

同时要防一个副作用：**为了快而乱回**。首响的目标是"确认收到 + 问出关键信息 + 给出下一步"，不是当场报底价。首响就问清四件事：目的国、采购品类与数量、当前供应商、决策时间表。

## 自主开发补的是平台的三个短板

平台解决不了的三件事，正是自主开发的价值所在：

**1. 客户资产不属于你。** 平台客户认的是平台，换个供应商成本很低。自主开发的客户认的是你——你的产品理解、你的响应、你的方案。这类客户复购率高、议价空间大。

**2. 大客户不在平台上比价。** 年采购千万级的买家通常有稳定供应链，不会在平台上公开询价。要接触到他们，只能靠展会、领英、行业协会、老客户引荐。

**3. 产品迭代信息拿不到。** 平台询盘多是"标准品比价"，很难得到深度需求。自主开发过程中和客户的技术沟通，才是产品改进的一手信息。

两条线的资源配比建议（不是标准，是起点）：

- 平台：保证基础曝光与询盘量，控制在"能覆盖固定成本 + 合理利润"的投放强度，不盲目加 P4P
- 自主开发：每个业务员每周固定 8-10 小时用于主动开发（领英加人、谷歌搜客户、老客户回访），纳入考核而非"有空再做"

## 两条线的客户查重与归属

渠道一多，最现实的冲突是**同一个客户被两条线各跟一遍**：

- 平台询盘来的客户，业务员 A 在跟；同一家公司的采购经理在领英上被业务员 B 加了
- 老客户在平台上用小号询价比价，业务员当成新客户报了更低的价
- 展会上来的客户，恰好也是平台上的老询盘

这类问题不解决，损失的不只是效率，还有价格体系和客户信任。

处理原则：

1. **以公司为主体查重，不以联系人为单位**：按公司域名、公司名（含简称与当地语言写法）查重，同一公司多个联系人归到同一客户下
2. **来源只记首次**：客户归属按"首次有效接触"判定，来源字段记录首个渠道，后续渠道作为"二次触达"补充记录，不覆盖
3. **老客户询价必查历史价**：报价前系统提示该客户的历史成交价与最低报价，防止自相残杀
4. **平台账号与 CRM 打通**：平台询盘导入时自动查重，命中的直接路由给归属业务员，避免重复开发

## 一套客户视图：数据怎么打通

渠道协同的终点是**一个客户一张卡，能看到他所有的接触痕迹**：

- 平台询盘记录（哪条产品、什么时候、问的什么）
- 邮件与 WhatsApp 往来
- 报价单与成交记录
- 展会见面记录
- 领英等社媒触达

有了这张卡，才能回答真正有价值的问题：

- 这个客户是从哪个渠道来的、花了多少钱、成了几单？（渠道 ROI）
- 平台来的客户，二次开发后复购率如何？（渠道质量）
- 某个国家的客户，主要从平台来还是自主开发来？（市场策略）

配套需要的两个能力，选型时要专门确认：

1. **来源字段可多级**：一级渠道（平台/展会/自主开发/老客介绍）+ 二级细分（阿里国际站/中国制造网/广交会/领英…），不能只有一个自由文本框
2. **渠道成本可记账**：平台年费、P4P 消耗、展会费用能按期间录入，才能算出单渠道的单客成本

## 自检清单

- [ ] 平台询盘是否统一进一个池子，而不是分散在各账号？
- [ ] 是否有值班表与移动端提醒，能做到 5-30 分钟内首响？
- [ ] 首响模板是否按询盘类型分层，而非一封通用回复？
- [ ] 首响时效是否纳入考核？
- [ ] 是否算过"单个成交客户的获取成本"，并按产品线/国家拆分？
- [ ] 自主开发是否有固定时间投入并纳入考核？
- [ ] 客户查重是否按公司主体（域名/公司名）而非联系人？
- [ ] 报价前是否会提示该客户的历史成交价与最低报价？
- [ ] 客户卡片能否看到跨渠道的全部接触记录？
- [ ] 渠道费用是否可记账，能算出单渠道 ROI？
