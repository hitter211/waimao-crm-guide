## 从一个人到三五个人，变化的不只是人数

SOHO 阶段你的工具是"一个人的外脑"：Excel 记客户、微信聊客户、备忘录记跟进。这套打法一个人用完全没问题。

但当你开始加人——不管是招业务员、找合作 SOHO 分单、还是带个跟单助理——原来的模式会接连出问题：

- **客户在个人微信里**：新人接手老客户时，对接历史、报价底线、恩怨情仇全在老板手机里
- **跟进靠口头**："那个土耳其客户你问下老陈"——问了三次没结果
- **撞单靠自觉**：两个业务员同时跟进同一个展会上来的客户，谁的客户说不清
- **进度靠问**：订单做到哪一步了，老板挨个问一遍才知道

这些问题不是"人不行"，是协作模式变了而工具没跟上。

## 第一个 hires：先加协作再谈系统

很多 SOHO 第一步是招人，第二步才发现需要系统。顺序反了——**先确定协作规则，再选承载规则的工具**：

1. **定客户归属规则**：按客户、按区域还是按渠道？展会上来的公共询盘怎么分配？规则定了才能进系统
2. **定沟通渠道**：客户沟通进企业微信/邮件（可归档），还是允许个人微信？这个决定后面所有"客户资产"归属
3. **定跟进节奏**：多少天必须跟进一次、超期谁提醒？规则要能写进系统变成自动动作
4. **定交接流程**：人走了/休假了，客户和订单怎么移交？一开始就定好，别等第一次离职时手忙脚乱

## 客户归属：小团队最大的隐性冲突源

3 人以上团队里，客户归属纠纷的破坏力远超想象：轻则业务员互相提防不共享信息，重则核心业务员带着客户出走。

**事前防，别事后判**：

- **录入即归属**：客户邮箱/手机录入系统时查重并锁定归属，后录入者自动提示撞单，由主管裁定——把"谁先录的"变成可查的客观事实
- **公共资源池规则**：展会名单、平台询盘进公共池，认领有时限，认领后转私人池；超时不认领自动回收
- **报备有效期**：长期未跟进的客户（比如 90 天无跟进）可设置回收进公共池，避免"占着不跟"
- **离职继承**：账号停用但数据保留，客户一键移交接手人，历史跟进记录原样可查

## 工具升级的三个阶段

**阶段一：1-2 人，协作表就够。** 共享表格 + 企业微信，重点是把客户信息从个人手机挪到共享处。此时上重系统是浪费。

**阶段二：3-5 人，轻量 CRM 上场。** 需要的能力：客户查重与归属、跟进提醒、简单报价单、撞单提示。选型要点是**上手快**——小团队没有IT，系统比人笨就没人用。

**阶段三：5 人以上或年单量过百，考虑业务财务一体化。** 订单、出运、收款、退税进同一套流程，跟进记录关联到订单而非散落。此时"客户管理"和"订单管理"分家会造成两本账。

各阶段的关键切换信号：

| 信号 | 该做什么 |
|---|---|
| 出现第一次撞单纠纷 | 立即上客户查重归属（阶段二） |
| 出现第一次客户交接 | 立即规范交接流程，历史记录可查 |
| 订单需要两个人接力跟进 | 订单流程要进系统（阶段三） |
| 老板每周花半天对账 | 收款核销与订单打通 |

## 踩坑实录：小团队常见错误

- **上了重系统没人用**：功能再多，业务员嫌麻烦就不用，最后回到 Excel。小团队选系统，"业务员愿意填"比"功能全"重要
- **系统里只有客户名没有跟进记录**：系统成了通讯录。原因是跟进不强制、无提醒。解决方式是定跟进节奏并让系统提醒，而不是靠自觉
- **权限一放到底**：小团队图省事全员管理员，离职时才发现谁都能导出全库。权限按需给，导出留痕
- **把系统当监工用**：只拿系统查"你几天没跟进"，业务员会抵触。系统的正确用法是帮业务员记事、提醒、生成报价单——先让他觉得有用

## 自检清单

- [ ] 客户录入有查重与归属锁定吗？
- [ ] 公共询盘的分配规则写下来了吗？
- [ ] 长期未跟进客户有回收机制吗？
- [ ] 新人接手老客户时，能自助看到完整跟进历史吗？
- [ ] 客户沟通沉淀在可归档的渠道里吗？
- [ ] 离职交接的流程演练过一次吗？
